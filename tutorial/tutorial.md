# Locus 上手指南

适用于 Locus 0.19.x。本指南只讲"装好、配好、跑起来"，进阶用法见 [进阶指南](./tutorial-v2.md)。

---

## 开始之前

三件事先说明白，能省掉后面的困惑。

**第一，Locus 不附带任何模型渠道。** 你需要自己有 AI 供应商的 API Key（OpenAI、Anthropic、DeepSeek、Kimi、智谱、各类 Coding Plan 等都支持）。应用本身不注册账号、不提供额度，打开就能用，但没配渠道之前它不能对话。

**第二，它是一个本地程序。** 配置、会话、记忆都存在你自己的机器上，默认目录是 `~/.proma/`。没有云端同步，也没有"换台电脑登录就能接着用"。数据迁移见「设置 → 数据迁移」。

**第三，本项目是基于 Proma 的修改版。** 你可以修改、分发，但分发时要遵守 AGPL-3.0。具体条款见 [README 的许可证部分](../README.md#许可证)。

## 安装

### 直接下载安装包

从 [GitHub Releases](https://github.com/jansfer/Locus/releases) 下载对应平台的安装包：

| 平台 | 文件 |
| --- | --- |
| macOS Apple Silicon / Intel | `.dmg` |
| Windows amd64 / arm64 | `.exe` |
| Ubuntu / Debian amd64 / arm64 | `.deb` |
| Linux amd64 / arm64 | `.AppImage` |

macOS 首次打开若提示来源不明，在「系统设置 → 隐私与安全性」里允许一次即可（当前安装包未做代码签名）。Linux 的细节见 [Linux 说明](../docs/linux.md)。

### 从源码运行

```bash
bun install
bun run dev
```

需要 Bun，不需要 npm 或 pnpm。

## 首次启动

第一次打开会进入新手引导，引导结束后建议去「设置 → 通用设置」里把环境检测过一遍。它检查的是 Agent 干活时真正会用到的东西：Git、Node、Bun、ripgrep 之类的命令行工具。缺了不致命，但少了它们，Agent 在处理代码和文件时会退化成"只能读写、不能检索"。

如果你只打算用 Chat 模式聊天，这一节可以跳过。

## 配置模型供应商

入口：**设置 → 模型配置**。

一个"渠道"就是一条到你供应商的连接，包含三样东西：渠道类型、Base URL、API Key。加上之后还要启用具体模型，Agent 才有模型可用。

### 操作顺序

1. 点「添加配置」，选择供应商类型。类型决定了请求协议（Anthropic Messages / OpenAI Chat Completions 等），选错了会一直报协议错误。
2. 填 Base URL 与 API Key。官方直连通常留默认地址即可；用中转站才需要改。
3. 保存后进「已启用模型」，把你要用的模型勾上。
4. 回到主界面新建会话，在输入框附近选择模型。

### 几点经验

**中转站要谨慎。** 用非官方地址时应用会弹一次风险提示，这不是走过场：中转方能看到你的完整对话内容，也能篡改模型返回。先用不敏感的测试内容验证。

**模型不是越多越好。** 每个启用的模型都会进入选择列表，列表太长时选模型本身就变成负担。日常留三五个够用。

**视觉助手是独立配置的。** 入口在「设置 → 视觉助手」，它负责图片理解——主模型不支持看图时，图片会转给这里的模型处理。只用文本可以不配。

**代理设置**在「设置 → 代理设置」，需要走公司代理或本地代理时在那里填。

## Chat 和 Agent 该选哪个

两种模式共用同一套渠道和模型配置，但工作方式完全不同。

### Chat 模式

一问一答。能读你手动附加的文件，但不主动翻你的项目目录，不执行命令，不改文件。

适合：查资料、解释概念、改写文字、对比几个方案、写一段不需要落盘的代码。

判断标准很简单：**如果答案只是要你读到，用 Chat。**

### Agent 模式

有工具。能读写文件、执行命令、开终端、开浏览器、联网检索、跑定时任务、调用 Skills 和 MCP。

适合：改一个仓库里的代码、整理一批文件、把重复流程做成自动化、需要真实执行才能得出结论的任务。

判断标准：**如果答案需要动手才能得到，用 Agent。**

### 计划模式

Agent 在动手前先给出一份计划，你审阅、修改、批准之后它才执行。适合改动范围大的任务——你不想等它跑完二十步才发现方向错了。

## 第一个 Agent 任务

按这个顺序走一遍，比读十篇教程有用。

### 1. 建一个项目

项目对应磁盘上的一个真实目录。你可以新建空目录，也可以直接指向已有的文件夹——后者更常见，比如你正在开发的一个仓库。

新建项目后，建议让 Agent 顺手写一份 `AGENTS.md`：

> 读一下这个项目的结构和主要文件，帮我写一份 AGENTS.md，说明项目是做什么的、代码怎么组织、常用的命令有哪些、有哪些约定需要遵守。

这份文件会在该项目下的每个会话里被自动注入，等于给 Agent 一份长期有效的项目说明书。

### 2. 建一个会话

会话是一次具体任务。原则是**一个会话只做一件事**。

这个原则不是洁癖。会话越长，上下文越浑浊，模型越容易在无关信息上犯错。做完一件事就结束，换下一件开新会话。

### 3. 把文件给 Agent

三种方式：

- 从右侧文件区把文件**拖进输入框**
- 输入 `@` 引用项目里的文件
- 直接把文件放进项目的会话文件夹

拖进输入框的文件会进入当前会话的文件夹，只对这个会话可见。项目级长期要用的资料应该放在项目目录里，而不是每次拖一遍。

### 4. 描述任务，然后看它干

第一次用建议在旁边看着：终端输出、文件改动、工具调用都在界面上可见。发现方向不对立刻打断，比等它跑完再返工省时间。

## Skills 与 MCP

**Skills** 是可复用的操作手册。它不是一个插件，而是一段写给 Agent 看的说明书：什么时候该用、按什么步骤做、有哪些坑。放在工作区的 Skills 目录里，Agent 按需加载。

**MCP** 是外部工具协议。把外部服务（数据库、项目管理、企业内部接口）接进来，Agent 就能调用它们。

两者都是**按项目隔离**的。这不是限制，是保护：Skills 和 MCP 越多，Agent 的选择成本越高、出错概率越大。只给当前项目装它真正需要的。

内置的那批 Skills（文档处理、PPT 生成等）可以直接用。需要对接外部服务时再去配 MCP。

进阶用法见 [进阶指南](./tutorial-v2.md)。

## 远程连接

入口：**设置 → 远程连接**。支持微信、飞书、钉钉、Slack 四种。

配置完后，你可以在手机上给机器人发消息，Agent 在你的电脑上执行，结果回到手机。适合"离开工位但想让任务继续跑"的场景。

每一类机器人都需要先在对应平台创建应用、拿到凭据，再填进 Locus。Slack 和飞书都提供了生成应用清单的入口，照着建应用比手动点选快。

这部分配置细节较多，第一次配建议一次只配一个平台，跑通再配下一个。

## 常见问题

**打开就能聊天吗？**
不能。必须先配渠道和模型。

**数据存在哪？**
`~/.proma/`。里面的 `settings.json` 是配置，`agent-sessions/` 是会话，改坏了可以在「设置 → 磁盘管理」里看到用量，也可以整体备份这个目录。

**能装在自己的服务器上给别人用吗？**
技术上能，但对外提供网络服务会触发 AGPL-3.0 的源码公开义务。先读许可证，别先上线。

**为什么 Agent 有时不用我给的 Skill？**
Skills 的触发依赖描述写得准不准。写清楚"什么时候用、解决什么问题"，比堆砌步骤有效。

**升级会不会丢数据？**
不会。安装包覆盖安装即可，数据目录不动。
